# Field-aware fusion: frozen feasibility protocol

Registered 2026-09-06 before encoding/training, following the user's explicit request to test arXiv:2608.02880. One bounded offline research exception to ADR-0029; no new production component, no test-A/test-B run, no promotion decision.

Question: does a tiny learned fusion head over field-specific similarities improve unseen DEV queries compared with the same training recipe over concatenated similarities?

- Corpus: all 10,123 SKILLRET train skills. Evaluation: existing frozen 1,000-query DEV. No test files loaded.
- Training: first 2,000 eligible train queries ordered by SHA256(id). Exclude DEV query IDs, exact normalized DEV query text, all DEV gold skill IDs, and exact normalized full-document duplicates of DEV gold skills. This is an unseen-labelled-skill evaluation over a known document bank; unseen semantic duplicates and pretraining contamination remain possible.
- Model: local generic Qwen3-Embedding-0.6B revision 97b0c614be4d77ee51c0cef4e5f07c00f9eb65b3, frozen, fp16 RTX4090. No teacher fine-tuning. Fields name/description/body (own frontmatter stripped); flat concatenation. Max 1,024 encoder tokens per representation; full text for TF-IDF. Field variant has a larger aggregate encoder token budget: NOT an exact paper reproduction or pure structure-only ablation.
- Query prompt: the model's documented generic retrieval prompt, identical across arms. L2-normalized TF-IDF unigram with sublinear TF, lowercase, standard sklearn tokenization; fit on documents only. Dense cosine, one query embedding shared across all fields.
- Six fixed arms: shipped sparse F0 replay (context only); flat uniform hybrid (2 scores); field uniform hybrid (6 scores); flat MLP (2->16->1); field MLP (6->16->1); sparse-field MLP (3->16->1). No hyperparameter sweep or DEV early stopping. Sparse-only arm isolates the marginal need for query-time dense.
- Training pairs: every annotated positive plus hard negatives from top20 of each of eight score channels plus20 random skills, with gold removed from negatives. Possible unlabelled positives are a limitation. Standardization fit on training pairs only. Fixed seed20260906; Adam lr0.003,30epochs, batch4096, balanced BCE. No feature of identity or query label is fed to MLP.
- Evaluation: root scope; same product policy_filter and select(admissible=...) for all new arms; rank candidate union capped200, k4, inherited closure. Abstention disabled identically for new arms because no negative labels exist; no NO_SKILL claim. Shipped replay has its own abstention/scorer and is a descriptive comparator, not an isolated ablation.
- Metrics: Hit@1, Recall@10, nDCG@10 (binary qrels), all-gold injection@4, paired query-bootstrap95% CI for field vs flat and dense-field vs sparse-field. Report multiple arms without confirmatory significance claims. Save per-query outputs, train/eval IDs, file/model hashes, versions and timings.
- Success for further study: field MLP improves R@10 by >=2pp and CI excludes0 versus flat MLP, without >1pp all-gold@4 regression. This only nominates a future preregistered product-path holdout experiment; it cannot admit a model. An inconclusive/negative spike closes this configuration, not the research hypothesis.
- Runtime/compute bound: local only, no download/API/cloud jobs, <=30min encoding; abort on OOM/unavailable model instead of changing scientific settings. Cache is local ignored output; source/report/small weights are reviewable.

Pre-training correction (no outcomes inspected): independent CTO review found that excluding DEV gold from positive training queries did not exclude these documents from mined negative pairs. The first process was stopped during body encoding, before features/training/evaluation. All blocked DEV gold/document-duplicate IDs are now excluded from negative pairs too, without replacement. All arms and optimization settings remain fixed. Name/description embeddings from the interrupted run can be reused only after the train/dev IDs and input-file hashes match the saved pre-training manifest. Cache identity includes the unchanged model/prompt/max length by the fixed protocol; no encoded text changed. The original manifest is retained. This corrects implementation to the stated disjoint labelled-skill protocol rather than selecting on outcomes.
