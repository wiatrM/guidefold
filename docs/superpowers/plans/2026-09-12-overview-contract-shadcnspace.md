## Contract 1.3.0 field names (fixed; used verbatim by every task)

| DTO / endpoint | Addition | Semantics |
|---|---|---|
| `Usage` | `previous:obj?` = `{window:{from:ts!,to:ts!}, totals:UsageTotals!}` | The window of the same length that ends at `window.from` (anchored on the same watermark). Counts computed exactly like `totals`, same filters. `null` only when the report has no totals. A zero count is a real zero over that window, not Unknown; the UI decides whether a delta is meaningful (both windows must have `exposures > 0`). |
| `ProposalSummary` | `decision:obj?` = `{decision:{approve\|edit\|reject}!, actor:str?, at:ts?}` | The latest row of `gfm.decisions` for the proposal; `null` when undecided. `actor` is the principal id string already used by `ProposalDetail.decision.actor`. |
| `QueueItem.decision` | `actor:str?` | The user id recorded on the owner decision (`gfm.owner_queue`), `null` for a worker decision. |
| `FeedbackEntry` | `actor:str?` | The principal id of the person who rated through the UI (`source: "ui"`); `null` for adapter-originated judgments. Stored on the `skill_feedback` event payload as `actor` (additive field; `tools/telemetry/ledger.py` only checks required/nullable fields, so an extra field is accepted). |
| `GET {org_base}/audit` | role `member` (was `owner`) | An owner reads every row; a member reads only rows whose `actor` equals their own principal id. Same page shape, same cursor. |

`contract_version: 1.3.0`, changelog entry 1.3.0 dated 2026-09-12 naming the four additions and the Overview (`/home`) that consumes them.
