## Why 0002 and 0011 are missing

Both were written, then deleted rather than kept as `Status: Superseded` stubs, once the decision
they recorded turned out to be wrong before anything downstream depended on them:

- **ADR-0002** assumed the tool could mint the registry's `skillId` itself
  (`urn:skill:meridian:<node>:<name>`). Verified testing against the real Agent Registry showed the
  URN is server-assigned; ADR-0008 records what is actually true and says so in its own Status
  line.
- **ADR-0011** proposed dedicated per-skill Git repositories. A workflow analysis showed the
  conflict risk motivating it was mostly synthetic (caused by committed generated files, not by
  skill edits), and dedicated repos were not workable inside the partner's monorepo policy.
  ADR-0018 records what replaced it.

Deleting outright, rather than leaving a one-line "Superseded" file, was itself a decision, not
an accident — `docs/MVP.md` §8 is where that trade-off is recorded so this gap is not a mystery.

## Adding a new ADR

Copy the format of an existing ADR (title as `# ADR-NNNN: <decision, in one line>`, a `Status:`
line, `## Context`, `## Decision`, `## Consequences`). Use the next unused number — do not reuse
0002 or 0011. Set `Status: Proposed` until the decision owner accepts it, then add a row to the
index above in the same PR that flips it to `Accepted`. If the new ADR changes or replaces an
earlier one, add a `Superseded by` / `Amended by` note to *both* files' `Status:` lines, not only
the new one. See [`CONTRIBUTING.md`](../../CONTRIBUTING.md) for the PR process.
