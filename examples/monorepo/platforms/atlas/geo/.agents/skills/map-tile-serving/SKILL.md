# Map tile serving

## When to use / when NOT to use
Use this skill when you:
- expose a geo layer as vector tiles at `/v1/tiles/{layer}/{z}/{x}/{y}.mvt`
- change `platforms/atlas/geo/tiles/config.yaml` (zoom range, tolerance, cache TTL, properties)
- add a generalised low-zoom representation of a large layer
- debug missing, oversized or slow tiles

Do NOT use it for:
- designing the tables or H3 columns behind a layer; that is `geospatial-indexing`, loaded with this skill
- raster imagery or basemap hosting (served by the relay deployment layer, not atlas)
- client-side styling of layers

## Steps
1. Confirm the layer follows `geospatial-indexing` (`geom`, `h3_cells`, indexes). The tile server
   refuses layers whose manifest lacks `h3Resolution`.
2. Add a `layers.<name>` block to `tiles/config.yaml` with `layerVersion`, `minZoom`, `maxZoom`,
   `tolerance` (metres per zoom step), `cacheTtl` and the `properties` allow-list. Unlisted
   properties are never emitted in a tile. Values omitted fall back to `defaults`.
3. If `maxZoom - minZoom > 8`, add a `generalize` section: below `generalize.zoom` the server
   aggregates rows by H3 parent cell (`h3ParentResolution`) and emits one feature per cell with a `count`.
4. Run `tilectl lint tiles/config.yaml` and `tilectl bench <layer> --zooms <min>,<mid>,<max>` locally.
5. Register the tile route through the generated OpenAPI router (see `atlas-api-conventions`); the
   handler only sets `Content-Type: application/vnd.mapbox-vector-tile` and the cache headers.
6. Add the layer to `tiles/config.yaml` `warm` if it is on an analyst default map.

## Conventions specific to this scope
- Tiles come from a single `ST_AsMVT` query per layer per zoom; the SQL template lives in
  `tiles/sql/<layer>.sql.tmpl` and is rendered from `config.yaml`. No hand-written tile SQL in Go.
- Tile size budget is 500 KB compressed. `tilectl bench` fails above that; fix by raising `tolerance`,
  lowering `maxZoom` or adding `generalize`, in that order.
- `maxZoom` never exceeds 16 for polygon layers and 18 for point layers; `minZoom` below 4 requires
  a `generalize` section.
- Cache keys are `tile:<layer>:<layerVersion>:<z>/<x>/<y>`; bump `layerVersion` whenever the SQL
  template or property list changes. Never purge the cache by hand.
- The `properties` allow-list must not contain fields classified above the layer's declared label
  (see `security:classification-labels`); tiles are cached without per-caller context.
- Zoom 0–3 of layers in `warm` are pre-rendered at release time and shipped as static files.
- The tile server is stateless; all per-layer configuration comes from `config.yaml`, never from env vars.

## Verify
- `tilectl lint platforms/atlas/geo/tiles/config.yaml` exits 0.
- `tilectl bench <layer> --zooms <minZoom>,<mid>,<maxZoom>` reports p95 under 200 ms and no tile
  above the size budget.
- `curl -sI localhost:8080/v1/tiles/<layer>/8/128/85.mvt` shows the MVT content type,
  `Cache-Control: public, max-age=<cacheTtl>` and an `ETag`.
- `go test ./platforms/atlas/geo/tiles/...` decodes a rendered tile and checks only allow-listed
  properties are present.
